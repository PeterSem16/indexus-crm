---
name: Call-review event provenance
description: Rules for what a manager may infer from call-linked contact history during quality review.
---

For quality review, do not present today's status-list confirmations or callback date as actions taken in a past call. Use the exact Mission-contact link, or for a legacy log with no link, only a unique contact matching the saved Mission and entity; never infer from a phone number. Match the call agent's history in a bounded wrap-up interval, ending before the next call. Display confirmed status-list steps and options (not the entire list) with their historical confirmation times. New confirmations need a snapshot of item type and label so later renames/deletions do not rewrite the review. A callback needs evidence of a real date transition, not a note-only edit or unrelated automation with no date; show the scheduling event's time separately from the future callback date. If that event is missing, the contact's current callback can be shown only as explicitly labeled **current state** and only when its scheduling item matches an option confirmed in the reviewed call; never silently substitute it for the call's historical result.

**Why:** Contacts and Mission definitions are mutable, and a later change can look like a decision made during the recorded conversation. Legacy calls can lack the direct contact link, while some Missions use only step items; filtering only `option` makes genuine confirmed choices vanish. Older history lacks some immutable item details; do not manufacture an answer from current state when that evidence is missing. Current-state fallback keeps scheduling information visible without claiming the date or note was set during that recording.

**How to apply:** Label the 15-minute wrap-up association as call-related, not an exact transcript-time guarantee. If strict audit attribution is required, persist the exact call ID with action history and make contact updates and their audit events atomic.
